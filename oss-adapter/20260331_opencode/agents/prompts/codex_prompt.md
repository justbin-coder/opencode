## 客户需求（仅分析 R01-R09）

### R01 [P0] 自然语言需求 → 结构化需求卡片
接受自然语言需求描述，输出结构化需求卡片（含需求编号、名称、优先级、功能目标、用户场景、时序图、验收标准、约束条件、接口定义）。准确率 ≥ 80%，单条 ≤ 30s。

### R02 [P0] 需求批量处理
支持一次输入 5～10 条需求进行批量处理，全部输出结构化 Markdown 卡片。

### R03 [P0] 需求输入格式支持
支持 Markdown 格式的需求文档作为输入来源。

### R04 [P0] C++ 单元测试自动生成
基于 C++ 源码文件 + 可选需求卡片，自动生成 gtest（优先）/ CppUnit 单元测试代码。分支覆盖 ≥ 70%，单函数 ≤ 2min。覆盖正常路径+边界条件+异常路径，中文注释，合理 Mock，禁止空断言。

### R05 [P0] 测试框架配置化
测试框架（CppUnit / gtest）通过配置文件指定，不硬编码。

### R06 [P0] 增量测试生成
支持在已有测试文件末尾追加新测试用例，不覆盖已有内容。

### R07 [P0] 测试样板学习
支持学习已有测试文件样板，生成编码风格一致的测试代码。

### R08 [P0] 自动编译验证
生成测试代码后自动调用 cmake 编译命令，解析编译器错误输出。基于 CMakeLists.txt 构建系统。

### R09 [P0] 编译错误自动修复（≤ 3 轮）
编译失败时自动解析错误、修复代码并重新编译，最多 3 轮。仅修复生成的单元测试代码的编译错误（语法/链接），不修复逻辑错误。3 轮后仍失败输出详细错误报告。
